Lesson 02 · Week 1 · API Basics

Schemas at the door

In lesson 1 you remembered to validate. Today you declare it. One win: the wall moves into the route definition, and the reply gets a wall too.

In one minute

  • Lesson 1 asked you to remember the wall. A wall you remember is a wall you forget.
  • Move the wall into the route itself. Fastify runs it for you, before your handler.
  • Add a second wall on the way out. It deletes any field you did not name.
  • Two walls: one stops bad input, one stops leaks.

The problem with lesson 1

Your api/server.ts works. But look at the shape of it: every handler starts with safeParse, then if (!parsed.success) return 400. Three routes, five copies of the same four lines.

That is not just ugly. It is a security shape: a wall you must remember to build is a wall you will one day forget. Route number nine, written at 6pm on a Friday, is the one with no safeParse.

Make the safe thing the default thing. Then forgetting is not possible.

Fastify already has a place to declare this: a schema on the route. It runs before your handler. If input fails, your handler never runs. Fastify: Validation and Serialization.

The two new ideas

IdeaWhat it means
Validator compilerYou teach Fastify, once, how to check a schema. Fastify ships with Ajv (JSON Schema). You will swap in Zod, so you keep one language for shapes.
Response schemaA shape for what goes out. Fields not named in it are deleted from the reply. This is output filtering.

Input validation stops attacks coming in. Output filtering stops leaks going out. You need both. OWASP calls the leak side Broken Object Property Level Authorization — number 3 on the API Top 10. It is usually just an object handed to send() with one field too many.

The code

Replace api/server.ts with this. Read the two set...Compiler blocks first — they are the whole lesson.

import Fastify from "fastify";
import { z, type ZodType } from "zod";

const app = Fastify({ logger: true });

// 1. Teach Fastify to check input with Zod. Written once, used by every route.
app.setValidatorCompiler(({ schema }) => (data) => {
  const r = (schema as ZodType).safeParse(data);
  if (r.success) return { value: r.data };
  const why = r.error.issues
    .map((i) => `${i.path.join(".") || "(root)"}: ${i.message}`)
    .join("; ");
  return { error: new Error(why) };
});

// 2. Teach Fastify to shape output with Zod. Unlisted fields are dropped.
app.setSerializerCompiler(({ schema }) => (data) =>
  JSON.stringify((schema as ZodType).parse(data)),
);

const CreateTask = z.object({
  title: z.string().min(1).max(200),
  done: z.boolean().default(false),
});
const TaskParams = z.object({ id: z.coerce.number().int().positive() });
const UpdateTask = z
  .object({ title: CreateTask.shape.title, done: z.boolean() })
  .partial();

// What the outside world is allowed to see. Note: no owner email.
const TaskPublic = z.object({
  id: z.number(),
  title: z.string(),
  done: z.boolean(),
});

// The stored row has a private field, on purpose, to prove the point.
type Task = z.infer<typeof TaskPublic> & { ownerEmail: string };
const tasks: Task[] = [];

app.get("/health", async () => ({ ok: true }));

app.post(
  "/tasks",
  { schema: { body: CreateTask, response: { 201: TaskPublic } } },
  async (request, reply) => {
    const body = request.body as z.infer<typeof CreateTask>;
    const task = { id: tasks.length + 1, ...body, ownerEmail: "jay@example.com" };
    tasks.push(task);
    return reply.code(201).send(task);
  },
);

app.get(
  "/tasks",
  { schema: { response: { 200: z.array(TaskPublic) } } },
  async () => tasks,
);

app.patch(
  "/tasks/:id",
  {
    schema: {
      params: TaskParams,
      body: UpdateTask,
      response: { 200: TaskPublic },
    },
  },
  async (request, reply) => {
    const { id } = request.params as z.infer<typeof TaskParams>;
    const task = tasks.find((t) => t.id === id);
    if (!task) return reply.code(404).send({ error: "not found" });
    Object.assign(task, request.body as z.infer<typeof UpdateTask>);
    return task;
  },
);

try {
  await app.listen({ port: 3000 });
} catch (err) {
  app.log.error(err);
  process.exit(1);
}

Every safeParse in a handler is gone. The handler now only does the job. The wall is in the route options, where you cannot help but see it.

One rough edge, told honestly: request.body is still typed unknown, so you cast it. A plugin (fastify-type-provider-zod) removes the cast. You are not adding it yet — casting once per handler is cheaper than a dependency you cannot yet explain.

Now attack it

Start the server: npx tsx watch server.ts in /Users/jay/learning/full-stack-learning/api. Predict the status code before each command.

# 1. works
curl -i -X POST localhost:3000/tasks \
  -H 'content-type: application/json' \
  -d '{"title":"buy milk"}'

# 2. empty title
curl -i -X POST localhost:3000/tasks \
  -H 'content-type: application/json' \
  -d '{"title":""}'

# 3. bad id in the path
curl -i -X PATCH localhost:3000/tasks/abc \
  -H 'content-type: application/json' \
  -d '{"done":true}'

# 4. read them back
curl -s localhost:3000/tasks

Test 1 is the money shot. You pushed ownerEmail into the object and handed the whole object to send(). Look at the reply: {"id":1,"title":"buy milk","done":false}. The email never left the building, because TaskPublic does not name it.

Test 2 and 3 now say something useful: "message":"title: Too small: expected string to have >=1 characters". That came from your why string in the validator compiler. One place, every route.

Check yourself

Why is a declared route schema safer than a safeParse call inside the handler?

Right: safety that depends on memory eventually fails. A declared wall is visible in the route and runs before the handler.

You add passwordHash to the stored row but not to TaskPublic. What ships?

Right: the response schema is a whitelist. Only fields it names survive serialization. That is output filtering.

Which parts of a request need a schema?

Right: a path param is just text a stranger typed after a slash. /tasks/abc proved it. Headers and query strings are the same.
