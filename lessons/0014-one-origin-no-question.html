Lesson 14 · Week 7–8 · API security

Avoiding cross-origin entirely

There is a third way to arrange your app, and it deletes the whole of lesson 13's configuration.

In one minute

  • Put the API on the same origin as the page, behind a path like /api.
  • Same origin means: no Origin header, no preflight, no allowlist, no cookie question.
  • You delete configuration instead of writing it. That is why most teams ship this.
  • The cost: one nginx file, and request.ip becomes the proxy until you fix it.

The picture

The three arrangements

The middle row is the one people miss: subdomains are cross-origin (so CORS is on) but same-site (so the cookie behaves). Lesson 13's two words, doing real work.

The nginx file

server {
  listen 443 ssl;
  server_name app.com;

  location /api/ {
    proxy_pass http://127.0.0.1:3000/;   # trailing slash strips /api
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }

  location / {
    root /var/www/app;
    try_files $uri /index.html;          # SPA fallback
  }
}

The cost, said plainly

Every request now arrives from 127.0.0.1. Lesson 12's IP floor is counting nginx, not your users — so one key for everybody. The fix is trustProxy in Fastify, switched on only once nginx is the thing writing that header.

Same family as lesson 11: a rate limit is only as good as its key, and a proxy changes the key underneath you.

Check yourself

Why is trustProxy dangerous to enable too early?

x-forwarded-for is just a header. If nothing you control overwrites it, an attacker sets it to a new value per request and your per-IP limit counts to one forever.

Do this

  1. Read deploy/nginx.conf. It is short and you will read it again at deploy.
  2. Make development match production: put Vite's dev proxy on /api, so you never debug a CORS problem that will not exist in production.

See it drawn

Same page, same API, same cookie. The only difference is the URL you fetch.

One origin

Both columns have the same cookie row. That is the half of the homework that had no knob — SameSite never had to change.

The two costs. Same-origin is not free.

1. request.ip becomes 127.0.0.1. Every user shares one rate-limit bucket. Fix in week 11–12: Fastify({ trustProxy: true }), and only ever behind a proxy you control.

2. The preflight is gone. A cross-origin write needed an OPTIONS a hostile page could not get. Now there is nothing to ask for — so SameSite=Lax is doing CSRF defence alone.
