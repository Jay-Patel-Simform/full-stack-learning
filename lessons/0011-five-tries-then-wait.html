Login throttling

Every route is behind a gate now — except the one that hands out the keys. The interesting part is what you count.

In one minute

  • Login has no gate, and does 252 ms of expensive work per attempt.
  • Counting per IP does not work — an attacker rents thousands of them.
  • Count the thing they have only one of: the email.
  • Do not lock the account. Back off instead. A lockout is a free denial-of-service button.

The picture

The idea

Two attacks, and they need different keys.

AttackOne of these, many of those
Credential stuffingone email, many stolen passwords
Password sprayingone password, many emails

The default that every rate-limit library ships is request.ip. It is the wrong key for a login, because the IP is the cheap part for the attacker.

Back off, do not lock

A lockout after five failures looks strict and is a gift: I fail your login five times and you cannot get in. Doubling the wait costs an attacker everything and a real person almost nothing, because a real person types the right password on try three.

exponential backoff — wait 1s, then 2, 4, 8, 16… up to a 15 minute cap. The wait grows faster than the attacker can work.

The code

// src/auth/throttle.ts
const fails = new Map<string, { n: number; until: number }>();
const MAX_KEYS = 10_000;   // any store keyed on caller input, the caller can fill

export function blockedFor(email: string): number {
  const e = fails.get(email.toLowerCase());
  return e && e.until > Date.now() ? e.until - Date.now() : 0;
}
// src/routes/auth.routes.ts — ORDER MATTERS
const wait = blockedFor(body.email);
if (wait) return reply.code(429).send({ retryAfter: wait });  // 1st: a Map lookup

const user = await findUser(body.email);                       // 2nd
const ok = await verify(body.password, user.passwordHash);     // 3rd: 252 ms

The check runs before the hash. A blocked request costs you a Map lookup, not a quarter of a second of CPU.

Rate-limit the thing the attacker has only one of.

Check yourself

Why is locking an account after five failures a bad idea?

The lock is triggered by a stranger's failures but the pain lands on the real owner. You have handed the internet a button that disables your users.
