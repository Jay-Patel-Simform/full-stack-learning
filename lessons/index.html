Twenty-eight lessons, each one short. Read the rule; if it does not land, open the lesson. Rewritten 2026-09-07 to be shorter and more visual — the older, longer versions are still in lessons/long/.

How to use this page

  • Reading top to bottom takes about ten minutes and rebuilds the whole story.
  • Each lesson is ~5 minutes plus a small task at the end.
  • One page with just the rules: the whole arc.

Week 9–10 · The front end

24403 vs 404Tasks on screen. 403 is about you and runs first; 404 is about the row and is deliberately vague.
25Mutations from the front endThe first write from the page. Say where you want to end up, and let the reply be the new row.

28204 responses and cache updatesDeleting from the page. A 204 carries no body, so the id you filter by is the id you sent.

Week 11–12 · Deploy

27Env config with no defaultsOne misspelled variable switches off HSTS, the Secure cookie or the rate limit — and the app boots.
29Finishing a refactor: one readerFinishing lesson 27. One fact, one reader — and why an unfinished refactor has no failing state.
30Cursor paginationA list route with no limit. Cursor pagination, one query instead of two, and reading a plan.
31React Query cache and pagesuseInfiniteQuery and a “Load more”. The cache stops being an array, and tsc mentions only half of what broke.
32Testing a module you cannot importThe first front-end test. The blocker is the @/ alias, not the browser — and the test finds structural sharing.
33Query keys as questions?done= and ?q=. A filter is an input to the answer, so it belongs in the query key — leave it out and the click sends nothing at all.
34Log redactionThe log is a second wire out of your app, and it has no schema. { err } printed a password hash. Redaction is the net; choosing the fields is the plan.
35Globs and test discoveryYour suite said 154 when it should have said 155. The shell expands the glob before the runner sees it, and ** means one level in sh. A test you have never seen fail is not a test.
36Audit logs store copies, not pointers72 audit rows point at a deleted task and cannot say what it was. An audit log stores copies, not pointers — and onResponse is too late to take the copy.
37SQL NULL vs JSON nullA jsonb column can be empty, or it can hold the word null. IS NULL only sees the first. 3,960 of your audit rows are the second kind, and one word in Prisma decides which you get.
38Reading the audit logThe log gets a reader. audit:read is a power of its own — a MEMBER may delete a task and still not see who else did. The index you wrote decides the filters you may offer, and the refused read writes itself into the log.
39The audit page in the front endThe log gets a screen, and the browser turns out to keep two stale copies of the reply. can.includes("audit:read") is TS2345; at: Date is silent and prints raw ISO text. Checked vs believed.
40A believed type can check itselfLesson 39's gap, closed. A full validator costs 91.5 KB gzip for one small schema; a 15-line hand-written guard costs 0. Both catch the same wrong-type bug. No new dependency, 40 lessons running.
41The role that can erase the evidenceThe permission system under the app: database roles. Measured — REVOKE UPDATE, DELETE works even on the owner, TRUNCATE slips past it, the owner grants it back in one line, and the lock breaks 3 tests and 0 routes. Homework 9 answered: retention.
42Two database loginsWiring tasks_app in. APP_DATABASE_URL for the server, DATABASE_URL for migrations and tests, chosen by one ternary in src/db.ts. Four tests that ask the database to refuse (42501). Measured: a shell variable beats .env. Plus “hint vs gate”, taught instead of asked.
43Deleting the audit log on purposeRetention. pruneAuditLog() opens its own connection as the owner, because the app role is refused. Cron is the scheduler — no new dependency. AUDIT_RETENTION_DAYS, default 90, min(1) because 0 days means every row. Three tests, planted 400 days back so real rows are never in range.
51The resource nobody can seeProject has a model, a migration, a store, two routes and six tests — and 0 rows, because there is no GET route and no project:read action. Adding one word to VIEWER fails two tests on purpose (168/2), and both are allowlists doing their job. Then the rule that decides the gate: a where clause is a scope only when you chose its value — session id, no gate; URL id, gate. The projects screen, list plus create. 172. No new dependency, 51 lessons.
52The machine you can throw awayThe first container. Two deliberate failures teach it: HOST=127.0.0.1 is correct on a machine and unreachable inside a box, and localhost:5432 points at the box, not your Mac. The boundary moves from the bind address to the port publish — 0.0.0.0 plus -p, not a wall removed. .dockerignore as a security step: an image is a file, and docker run api cat /app/.env is all it takes. Layer order, and why there is no build stage. No new dependency, 52 lessons.
53One command, two machinesPostgres moves into a container of its own. compose.yaml: a named volume, a healthcheck, and a service name — db:5432 is real everywhere, host.docker.internal is real on one laptop. The lesson-41 role script aborts the database init, because init runs on an empty volume and the last line names "AuditLog". A grant is about rows that exist; a default privilege is about rows that do not yet. Split the file by when it can run, migrate deploy (never dev), and the only undo for a bad init is down -v. Zero TypeScript. 172. No new dependency, 53 lessons.
54The box that starts itselfThe five manual commands of lesson 53 become one. New docker-entrypoint.sh: set -e, migrate deploy, db execute for audit-lockdown.sql, then exec "$@". An image is a photograph of your source, not a window onto it — the stale COPY that made the seed crash, and up --build. migrate deploy is idempotent, and two containers racing on an empty database are safe because Prisma takes a Postgres advisory lock (measured). Migrations automate; the seed never does. Zero TypeScript. 172. No new dependency, 54 lessons.
55The database that is not on your laptopPostgres leaves the laptop for Neon (free, permanent, no card) while the container stays. Two lines of tasks_app.sql named laptop-only things — the database tasks and the role tasks — and the second would have failed silently. Fixed with psql’s :"DBNAME" and :"USER" (measured against the running container). Pooled vs direct: the app takes the -pooler host, migrations must not, because an advisory lock lives on one connection. The tasks_app password is rotated at last — Neon requires 60 bits — and then kept out of the SQL file with psql’s \getenv + :'literal', because lesson 56 commits that file and a secret committed once is history forever; .env.docker joins .gitignore. Move the database first: one change, one suspect. Zero TypeScript. 172. No new dependency, 55 lessons.
56The URL you can send to someoneThe app leaves the laptop too: a Render free web service built from the existing Dockerfile, Root Directory server (same build context compose gives it). .gitignore before git init — git add -A then read the index, because add is reversible and commit is forever. Env moves to a dashboard; PORT is given, not chosen, and HOST=0.0.0.0 or the deploy dies with a port message for a host mistake. Render is never told this app has migrations — ENTRYPOINT does it, and the Docker Command field overrides only CMD. NODE_ENV=production + TRUST_PROXY=true flip together, and Secure is emitted for the first time since lesson 29. Then the payoff failure: local page, deployed API, logged out — not CORS, SameSite=Lax, and the fix is one origin. Zero TypeScript. 172. No new dependency, 56 lessons.
