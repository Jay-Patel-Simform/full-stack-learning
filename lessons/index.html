61The deploy that is a fileLessons 56 and 57 built two Render services by typing into a web form, and left nothing behind — nobody can review a form. Both become one render.yaml at the workspace root. The trap: a file in the repo is a public file, so the environment splits by kind. Decisions (NODE_ENV, TRUST_PROXY, HOST, LOG_LEVEL) go in as value:, where a reviewer can argue with them; secrets go in as sync: false — the name in git, the value asked for once and stored by Render. PORT stays absent because Render sets it. Second rule: rootDir moves the service, not the paths — dockerfilePath and staticPublishPath are still written from the repo root. Route order survives the move: first match wins, so /api/* before /*. The loop is render blueprints validate, not a deploy. Zero application code. 172. No new dependency, 61 lessons.
62The header that says noEvery defence so far runs on the server and trusts the browser. A CSP instructs it — an allowlist of sources, sent as a response header, enforced against code you did not write. It fills the headers: key lesson 61 left empty, on the static site only (JSON renders nothing). The policy is derived from four facts checked in this repo, not copied from a blog: no inline script in the built index.html, self-hosted Geist, live style= attributes from Radix and motion, and a same-origin /api. So script-src 'self' is free, and style-src needs 'unsafe-inline' — named as a real weakening, with the rule that it must never migrate into script-src. connect-src is the last line: it blocks the exfiltration, not the script. Shipped as Report-Only first — observable before authoritative, the same shape as lesson 10’s migration. Zero application code. 172. No new dependency, 62 lessons.
63The headers you already haveLesson 62 said “check what you are already sent before adding any”; this is that check, run with curl -sI against the live site. It found that the CSP is not deployed — so the clean console proved nothing, because a page with no policy and a page with a perfect one produce the same silence. It also found the Blueprint names (tasks-web, tasks-api) do not match the live services, which answers lesson 61: applying it as written would create a second pair. Three parties send headers and none coordinates: helmet on the API, Render on the static site, your headers: block. Measured gap is two lines — Referrer-Policy (honest: already the browser default) and Permissions-Policy (the only real gain). HSTS, nosniff and X-Frame-Options deliberately not added. Loop is curl → deploy → curl → diff. Lesson 62’s open box closed by measurement: a proxied /api/* response keeps helmet’s own headers. Zero application code. 172. No new dependency, 63 lessons.
64The deploy you can still see the old ofLesson 63’s deploy landed — curl confirms all three headers, and the renamed services close lesson 61. So the queued cache-control lesson, now grounded in a measured gap: Render sends the same max-age=0, s-maxage=300 to index.html and to the hashed /assets/ bundles, though the two want opposite caching. max-age is the browser; s-maxage is the CDN — and the second one is your post-deploy staleness window. Fix is one path: /assets/* entry with max-age=31536000, immutable: safe because the guarantee lives in the filename, not a timer. Measured that a revalidation costs a 304 round trip, not bandwidth. index.html deliberately untouched. Unmeasured and flagged: whether Render keeps the previous deploy’s assets alive. Zero application code. 172. No new dependency, 64 lessons.
65The route nobody is logged intoThe first route with no session — CSP report-uri as the excuse, the shape as the point, because the invite-accept route needs the same thing. Opens with the argument against building it: with one user and the console open it buys almost nothing. Three defences lost and what replaces each: no auth (accept it), per-IP rate limit (now the only one, so a tighter per-route bucket), and no audit row — shouldAudit would write one per violation with no actor. Two traps grounded in his own app.ts: browsers post application/csp-report, so Fastify answers 415 until a parser is added; and strict zod is wrong here because the browser composes the body. Handler answers 204, logs three slice()d fields, never the whole report. Unmeasured and flagged: whether the CSRF hook 403s a report POST. 172. No new dependency, 65 lessons.
66The answers you already hadThree open items turn out to be questions, not features. (1) The body size limit has existed since the first commit — bodyLimit: 64 * 1024, sixteen times tighter than Fastify’s default — and it was asked for four times because it never appeared in a lesson. Measured: 80 KB is a 413, and lesson 65’s custom application/csp-report parser inherits the app limit. (2) Lesson 65’s unmeasured question, answered with a real headless Chrome: a CSP report carries Sec-Fetch-Site: same-origin and sails through allowWrite() on line 2 — 204, not 403. Cross-site it carries the page’s Origin, which is in ALLOWED_ORIGINS, so it passes for a reason that is not quite the reason you wanted. (3) Lesson 64’s asset check cannot run: the live bundle is still index-D1HMFRqX.js, so nothing has changed to compare. Found while looking: the live CSP is still Report-Only and the report-uri is in the working tree, not on the internet. Three new tests. 177. No new dependency, 66 lessons.
67The door marked exitThe forty-lesson-old note said “an owner cannot leave their own team”. Measured: nobody can leave, and for two unrelated reasons — VIEWER and MEMBER never had member:remove, while ADMIN and OWNER pass the table and die on the rank rule, because you are always exactly equal to yourself. One symptom, two bugs, hidden by lesson 8’s “one reply for two different noes”. The fix is a new action, not an exception in the gate: member:leave granted at VIEWER so every role inherits it, and passed no target, so the rank rule stays out entirely. One real refusal survives — the last owner would strand the team — and it is a 409, not a 403: the permission is fine, the state is not, and promoting somebody makes the same request work. SELECT … FOR UPDATE on the team row, because a transaction is atomicity, not isolation: at Read Committed two owners both count two and both leave. The front end gets the new action free via can, and two existing tests go red because both hard-code the VIEWER set — right to fail, update the expectation not the table. 182. No new dependency, 67 lessons.
68The first test that needed a browserThe streak ends, on purpose, with the reasoning out loud. disabled={isPending || name.trim() === ""} holds three real decisions and nothing has ever rendered it — node --test has no DOM, no JSX transform and no @/ resolver, and hand-rolling those three is a worse version of a solved problem. Vitest over Jest for one reason: vite.config.ts already holds the alias and the React plugin, and Vitest is Vite, so there is no second config to drift. jsdom over happy-dom — smaller (7.2 vs 8.6 MB unpacked) and more complete, and at three tests there is no speed to win; measured +43 MB and 69 packages (254M → 297M), four times the direct total — run du, never add up registry numbers. Three tests on NewTeamForm: the trim rule finally enforced, the trimmed value actually sent, and a 403 leaving the typed sentence on screen (lesson 26’s decision, now guarded). vi.spyOn(api, "post") instead of MSW; retry: false or the failing test times out; getByRole/getByLabelText so accessibility becomes load-bearing. Two predictions in the lesson turned out wrong when run and are corrected in place: the old node:test files do not survive the swap (Cannot bundle Node.js built-in under jsdom — convert them, mechanically), and toBeDisabled() really does throw Invalid Chai property. 12 web tests. Four new packages, and the streak ends at 67.
60The team that makes you its ownerA brand-new account signs in to “No teams yet” — a dead end, because POST /teams has never been called by anything but a test. The trap is a cache one: the 201 body is not a list row. TeamPublic is {id, name}; a row of GET /teams is TeamMembership, which adds role and can — computed by the server’s permission table, so the front end cannot invent it. Hence invalidate, do not setQueryData, and return the invalidation promise from onSuccess so navigation waits for the new list instead of landing on a team the cache has never heard of. Also the one route with no requirePermission, and not by omission: there is no teamId to hold a role in until the handler runs, and the row it writes makes you OWNER. Cache work in the hook, navigation in the component’s per-call onSuccess. Zero server change. 172. No new dependency, 60 lessons.
59The account nobody can makeThe page has a sign-in form and no sign-up form; POST /auth/register has never been called by a browser. The trap is that register answers 201 with a user and no cookie, while login answers 200 with the same body plus set-cookie — so seeding SESSION_KEY from the register reply renders a signed-in page over a signed-out browser. Fix: chain, do not trust — register, then login.mutateAsync with the same two fields, because only that call makes a session. mutateAsync not mutate: mutate swallows the error and a failed second call would look like success. The route lives inside RequireAnon, which both blocks signed-in visitors and does the post-signup redirect — no hand navigation. 409 and 429 need no new code: errorMessage and CREDENTIAL_ROUTES were already waiting. minLength={8} stays a hint; the wall is zod. Zero server change. 172. No new dependency, 59 lessons.

37SQL NULL vs JSON nullA jsonb column can be empty, or it can hold the word null. IS NULL only sees the first. 3,960 of your audit rows are the second kind, and one word in Prisma decides which you get.

57One origin, and the cookie comes backLesson 56’s 401 is deleted rather than fixed. The front end becomes a Render static site (free, no spin-down — files on a CDN, not a process) with two rewrite rules: /api/* → the API service, then /* → /index.html, in that order. A rewrite, not a redirect — a redirect sends the browser to the API host and the cross-site problem comes back with a spare round trip. No server change is needed because the session cookie has no Domain=: host-only, so it belongs to whatever host the browser asked. SameSite=None would also have worked and would have handed back lesson 29’s CSRF defence — do not loosen a defence to accommodate an accident. VITE_API_URL=/api, a path, and baked in at build time, not read at boot. Sec-Fetch-Site: same-origin is true for the first time. One open question left deliberately unmeasured: whose IP the per-IP floor now counts. Zero TypeScript. 172. No new dependency, 57 lessons.
58A 404 has an authorThe deployed page asks GET /api/auth/me and gets 404. Measured, not guessed: curl on the live URL returned {"message":"Route GET:/ not found"} — Fastify’s own words, carrying helmet’s default-src 'none', so the request arrived and the path was wrong. The rewrite destination was missing its /*. The star does two jobs: in the source it captures, in the destination it pastes — you can have the first without the second, and matching and forwarding are two decisions. The durable skill is reading who wrote the 404: your API (JSON + your headers) means fix the path; the CDN (bare HTML) means no rule matched; a 200 of index.html means rule 2 swallowed it. Check with /api/health, never /api/auth/me — a working me answers 401 to a terminal and hides the answer. Zero TypeScript. 172. No new dependency, 58 lessons.
