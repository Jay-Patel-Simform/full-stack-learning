Lesson 09 · Week 5–6 · RBAC

Scoped permission checks

An ADMIN can remove the OWNER. The bug is not a missing if — it is a missing argument.

In one minute

  • "An admin may remove a member, but not the owner" has three parts. Your function had room for two.
  • Add the third: the thing being acted on. can(role, action, resource).
  • The rule is one comparison: you may act only on somebody strictly below you.
  • The gate fetches the target, never the handler.

The picture

The idea

Say the rule out loud: "an admin may remove a member, but not the owner." Count the things in it. Three: the admin, the removing, the owner.

Your function had two slots. No amount of cleverness inside a two-slot function can express a three-part rule.

Now, who fetches the third fact? The target's role is in the database. Somebody has to go and get it. Not the handler:

A handler only runs after the gate said yes. So a check inside a handler is a gate you can forget to write.

That is lesson 7's argument again, one level up. A route with no gate looks obviously naked. A route with a gate and a hidden second rule in the body is the dangerous one, because it looks guarded.

The code

// rank: position in the ROLES array
const rank = (r: Role) => ROLES.indexOf(r);

export function can(role: Role, action: Action, resource?: { role: Role }) {
  if (!PERMS[role]?.includes(action)) return false;
  if (!resource) return true;
  return rank(role) > rank(resource.role);   // strictly below you
}
// the gate is now told HOW to find the target
requirePermission("member:remove", loadTargetMember)
//                                 ^ a Load function; the gate awaits it

The same one comparison closed a second hole for free: an ADMIN can no longer invite a new OWNER. You did not write that case. The rule found it.

Count the nouns in the rule you want. Then count the parameters you have.

Check yourself

Why not put the rank check in the route handler?

Handlers await queries all day. The problem is that a gate you must remember to write inside each handler is a gate that will be missing from one of them.
