Lesson 27 · Week 11 · Deploy

Env config with no defaults

Week 11 starts. Before the app can go anywhere, it has to say out loud what it needs. Right now it does not — and every safety wall you built in weeks 7–10 can be switched off by one misspelled variable, with no error, no log line, and a healthy 200.

In one minute

  • Your app reads 7 environment variables from 4 files. Nothing lists them. Nothing checks them.
  • Six of the seven fall back silently. Only DATABASE_URL is loud. A fallback means a missing value is indistinguishable from a correct one.
  • Measured below: NODE_ENV=Production silently drops HSTS and the Secure flag on your session cookie. TRUST_PROXY=1 silently turns the whole internet into one rate-limit bucket. Both boot fine. Both answer 200.
  • The fix is one file: src/config.ts. One zod schema over process.env, parsed once, at boot.
  • The safety variables get no default. No value, no boot — and the process exits 1, listing every problem at once.

The word pair

fail fast — refuse to start when the setup is wrong. The error arrives while you are still watching the deploy log.
fail quiet — start anyway, with a fallback. The error arrives weeks later, as a security incident nobody can date.

A default turns fail-fast into fail-quiet. That is what it is for — so only give one to a value where being wrong is obvious in a second.

Read line 2 again. One capital letter, and the session cookie your users carry all day is allowed to travel over plain http — the exact flag lesson 6 was about. Nothing logged it.

Line 3 is the one from deploy/nginx.conf. Behind nginx every request arrives from 127.0.0.1, so request.ip is the proxy: your 100-per-minute floor (lesson 12) becomes 100 per minute for the whole internet, and every audit row records the same address. TRUST_PROXY=1 is a completely reasonable thing to type. It reads as true. It is false.

Why these are worse than a crash. A crash at boot costs you five minutes and a deploy log. These cost you nothing today and everything on the day someone looks. Third member of the family you already know: the quiet strip (lesson 17), the missing querystring schema (lesson 20), and now the fallback default.

The code — type it yourself

1. server/src/config.ts — new file

import { z } from "zod";

// ? Read .env into process.env. Built into Node, so no dotenv at runtime.
// ! In production there is no file - the variables come from the environment.
try {
  process.loadEnvFile();
} catch {
  // ? no .env here, so process.env is already the whole story
}

// * Every variable this app reads, in one place, with its type.
// ! A .default() is a place a typo can hide. The four that decide whether
// ! production is SAFE have no default: no value, no boot.
const Env = z.object({
  DATABASE_URL: z.url(),
  NODE_ENV: z.enum(["development", "test", "production"]),
  ALLOWED_ORIGINS: z
    .string()
    .min(1)
    .transform((s) => s.split(",").map((o) => o.trim()).filter(Boolean)),
  // ? stringbool accepts true/1/yes/on and false/0/no/off, and REFUSES
  // ? anything else. `=== "true"` accepted everything and answered false.
  TRUST_PROXY: z.stringbool(),

  // * These three only decide where it listens and how loud it is. Being
  // * wrong is visible in one second, so here a default is honest.
  PORT: z.coerce.number().int().min(1).max(65535).default(3000),
  HOST: z.string().min(1).default("127.0.0.1"),
  LOG_LEVEL: z.enum(["silent", "error", "warn", "info", "debug", "trace"]).default("info"),
});

const parsed = Env.safeParse(process.env);

if (!parsed.success) {
  // ! console.error + exit(1), not throw: a stack trace buries the one thing
  // ! you need to read, and exit(1) is how the host knows the boot failed.
  console.error("Bad environment:\n" + z.prettifyError(parsed.error));
  process.exit(1);
}

// * Parsed, typed, and never read from process.env again.
export const config = parsed.data;

Note what config is now: PORT is a number, TRUST_PROXY is a boolean, ALLOWED_ORIGINS is a string[], and NODE_ENV is one of three literals. Every process.env read is a string | undefined; every config read is the type you actually wanted. The parse did the coercing once, at the door — the same move as the route schemas.

3. server/.env — three new lines

The four required variables now have to be somewhere, and in development that somewhere is .env. Without this, npm test will not start.

NODE_ENV=development
ALLOWED_ORIGINS=http://localhost:5173
TRUST_PROXY=false

The whole lesson is the difference between that screen and a 200.

Check yourself

Why does ALLOWED_ORIGINS lose its default and LOG_LEVEL keep one?

A wrong LOG_LEVEL shows up the first time you look at the output, so the fallback costs you a second. A wrong ALLOWED_ORIGINS falls back to localhost:5173, which is correct on your laptop and silently wrong in production — your own front end gets no access-control-allow-origin and you debug CORS instead of reading one line. The test for a default is never “is there a sensible value”; it is how long does being wrong stay invisible.

What did TRUST_PROXY=1 do before today?

process.env.TRUST_PROXY === "true" is false for "1", so Fastify ignored X-Forwarded-For and request.ip stayed 127.0.0.1 — nginx. Measured above. Every caller then shares one bucket in the 100/minute floor, and every audit row records the proxy. The other answer is the opposite mistake: trusting the header with no proxy in front, which is why this is opt-in and not always-on.

Why process.exit(1) rather than throw?

A thrown error prints a stack trace, and the one line you need — the variable name — is buried in it. More importantly the host (Fly, systemd, Docker) reads the exit code to decide whether the boot failed: a non-zero exit stops the rollout, and a crashed-on-import process may not. The console line is for you; the 1 is for the machine.

GapWhy it is still open
A misspelled optional variable is still silentEnv ignores keys it does not name, and it must — process.env holds PATH, HOME and forty others. LOG_LEVL=debug still does nothing. The defence is having no default, not the schema.
It does not check that the values are truez.url() proves DATABASE_URL is shaped like a URL, not that a database answers there. That is a health check, not a schema.
Secrets are still in a file on disk.env is fine for your laptop. In week 12 the same names come from fly secrets set and there is no file at all — which is exactly why loadEnvFile() is wrapped in a try.

Do this

  1. Run the grep at the top. Count the lines yourself before you trust my table.
  2. Write server/src/config.ts, swap the seven reads, add the three lines to .env. Then cd server && npm run typecheck && npm test. Expect 141 passing — this changes no behaviour, only what happens when the setup is wrong.
  3. Prove it fails. NODE_ENV=Production npm start. It must refuse to boot. Then TRUST_PROXY=banana npm start, then PORT=abc npm start. Three different messages, all naming the variable.
  4. Prove it still boots. npm run dev, then curl -i localhost:3000/health. Then NODE_ENV=production TRUST_PROXY=true ALLOWED_ORIGINS=https://app.example npm start and check the reply now carries strict-transport-security.
  5. Write server/.env.example — the same seven names, with fake values and one comment each. This is the file you commit; .env is the file you never do. Confirm .env is in .gitignore.
  6. Break it on purpose. Give NODE_ENV back its default: .default("development"). Now NODE_ENV=Production npm start boots happily with no Secure cookie again. That one word is the whole lesson. Put it back.
  7. Update the docs you contradicted. server/CLAUDE.md says “Everything has a working default, so npm run dev needs none of them.” That is now false for four of them. Rewrite that section from your schema.

safeParse collects every problem instead of throwing on the first, so a fresh server is one restart away from correct, not four. And the 1 is not decoration — it is how Fly, systemd or Docker learn the boot failed and stop the rollout.

A .default() is a place a typo can hide. Give one only where being wrong is visible in a second. PORT, HOST, LOG_LEVEL qualify. The four that decide whether production is safe do not.
