Lesson 08 · Week 5–6 · RBAC

Roles as membership rows

Last lesson you built can() and nothing called it. Today you give it a real role to judge, and four routes start answering 403.

In one minute

  • A role is not a column on User. One person can be OWNER here and VIEWER there.
  • The role belongs to the pair: this user, in this team. A pair is a row.
  • Make role a Postgres enum, so "ADMINN" cannot be stored.
  • One hook, requirePermission("member:invite"), reads the row and answers 403.

The picture

The idea

The tempting version is User.role. It breaks the first time somebody joins a second team, because there is one column and two answers.

Ask the question precisely: "what may Jay do in team 7?" The question names two things. So the answer lives on the pair of them.

enum — a type with a fixed list of allowed values, enforced by Postgres itself. A typo is rejected at the database, not discovered in production.

The code

enum Role { VIEWER MEMBER ADMIN OWNER }

model Membership {
  team   Team @relation(...)
  teamId Int
  user   User @relation(...)
  userId Int
  role   Role
  @@id([teamId, userId])      // one role per pair, enforced
}
// src/auth/require-permission.ts — a function that RETURNS a hook
export function requirePermission(action: Action) {
  return async function (request, reply) {
    const role = await getRole(request.params.teamId, request.user.id);
    if (!can(role, action)) return reply.code(403).send({ error: "forbidden" });
  };
}

// the route asks for a JOB, never for a BADGE
app.post("/teams/:teamId/members", {
  preHandler: requirePermission("member:invite"),
}, handler);

Notice the route says member:invite, not ADMIN. If you later decide MEMBERs may invite, you change can.ts and no route moves.

Routes ask for a job, never for a badge.

Check yourself

A stranger and a VIEWER both hit an admin route. What do they get?

One reply for two different noes. Different replies would tell a stranger that the team exists — a small leak, and free to avoid.

Do this

  1. npm test — 28 tests. Note the split: can() tests need no database, route tests need a real one.
  2. Over HTTP, as a MEMBER, try DELETE /teams/1. You want 403.
  3. Try to INSERT a membership with role = 'ADMINN' in psql. Postgres refuses.
