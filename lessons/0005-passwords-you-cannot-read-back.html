Hashing passwords with scrypt

The win: run select * from "User", stare at the row, and still not know the password. Not even you.

In one minute

  • A password goes in a shredder, not a locked box. You never need it back.
  • Add a random salt per user, so two people with the same password get different output.
  • Pick a hash that is slow on purpose. scrypt is already inside Node.

The picture

The idea

Encryption is a locked box: with the key you get the contents back. That is exactly what you do not want here. If you can read the password back, so can whoever steals your database.

Hashing is a shredder. Same input always gives the same shreds, and there is no route back. To check a login you shred the attempt and compare.

salt — random bytes mixed in per user. Without it, two people who both chose hunter2 get identical rows, and a precomputed table cracks both at once.
slow on purpose — a fast hash lets an attacker try billions per second. 252 ms per hash is invisible to your one user and ruinous to a cracker.

The code

// src/auth/password.ts
import { randomBytes, scrypt, timingSafeEqual } from "node:crypto";

const N = 16384, r = 8, p = 1, len = 64;

export async function hash(password: string) {
  const salt = randomBytes(16);
  const key = await scryptAsync(password, salt, { N, r, p, len });
  // the recipe travels WITH the hash, so you can turn N up later
  return `scrypt:${N}:${r}:${p}:${salt.toString("hex")}:${key.toString("hex")}`;
}

export async function verify(password: string, stored: string) {
  const [, n, r, p, salt, key] = stored.split(":");
  const attempt = await scryptAsync(password, Buffer.from(salt, "hex"), ...);
  return timingSafeEqual(attempt, Buffer.from(key, "hex"));
}

Store the recipe next to the shreds. Then you can turn the dial up in two years without locking anyone out.

Check yourself

Why is a deliberately slow hash the right choice?

Nothing makes a hash unreadable — an attacker can always guess and check. Slowness changes the economics: a billion guesses now costs years instead of seconds.

Do this

  1. Register the same password twice, as two users. The stored strings differ. That is the salt.
  2. time one login. You want roughly 250 ms.
  3. Look at the row in psql. Try to work out the password. You cannot.
