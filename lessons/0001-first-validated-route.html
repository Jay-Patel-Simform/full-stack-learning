Validating a route with zod

A server is a function that runs when a request arrives. Today you write one, and you make it refuse bad input.

In one minute

  • A server waits at a port. A request arrives, your function runs, you send a reply.
  • Check the request before your code touches it.
  • Then use the checked copy, never the raw one.

The picture

The idea

In the browser you validate a form so the user is not annoyed. On a server there is no user. There is whoever sent the bytes.

They can send anything: a number where you wanted a string, a missing field, ten megabytes of nothing. If your code touches that directly, it crashes or it stores rubbish.

So: one wall, at the door.

zod — a library where you write down the shape you want, and it tells you yes or no. Written down, not remembered.

The code

// src/routes/task.routes.ts
const CreateTask = z.object({
  title: z.string().min(1).max(200),
  done: z.boolean().optional(),
});

app.post("/tasks", async (request, reply) => {
  const parsed = CreateTask.safeParse(request.body);
  if (!parsed.success) return reply.code(400).send({ error: "bad input" });

  // parsed.data, NOT request.body
  return store.create(parsed.data);
});

The front end validates to be kind to the user. The back end validates to stay alive.

Check yourself

After a successful check, which object should your code use?

The raw body still holds anything extra the caller sent. The checked copy holds only what you named. Always use the checked one.

Do this

  1. Run the server. curl -X POST localhost:3000/tasks -H 'content-type: application/json' -d '{"title":"hi"}'
  2. Now break it on purpose: -d '{"title":42}'. You want a 400.
  3. Try -d '{}'. Also a 400.
