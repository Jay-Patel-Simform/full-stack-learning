Team-scoped routes

Four permissions have no route behind them, and the reason is one missing piece of the URL.

In one minute

  • PATCH /tasks/5 has no team in it, so the gate has no role to look up.
  • Put the scope in the URL: PATCH /teams/7/tasks/5.
  • Adding a required column to a table with rows needs three steps: expand, backfill, contract.
  • where: { ownerId } was a hidden permission. where: { teamId } is a fence. Different jobs.

The picture

The idea

The gate's first move is getRole(teamId, userId). If the request never said which team, there is no role, so there is no decision. That is why those four permissions were unreachable.

Fixing it means Task needs a teamId. And Postgres will refuse to add a required column to a table that already has rows — correctly, because it has no value to put there.

Expand, backfill, contract

-- 1. expand: add it, nullable. Nothing breaks.
ALTER TABLE "Task" ADD COLUMN "teamId" INTEGER;

-- 2. backfill: give the old rows a real value.
UPDATE "Task" SET "teamId" = 1 WHERE "teamId" IS NULL;

-- 3. contract: NOW put the wall up.
ALTER TABLE "Task" ALTER COLUMN "teamId" SET NOT NULL;
ALTER TABLE "Task" ADD CONSTRAINT ... FOREIGN KEY ("teamId") ...;

Three steps, no lost rows, no downtime. This is the answer to "how do I add a column to a live table" for the rest of your career.

where: { id, ownerId } is now out of task.store.ts. The gate decides. The query only scopes.

A permission needs a scope, so the scope goes in the URL.

Check yourself

Why add the column as nullable first?

NOT NULL is a promise about every row, including the ones already there. You have to give them a value before you can make the promise.
