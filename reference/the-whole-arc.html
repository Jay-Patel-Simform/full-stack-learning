Every lesson's one sentence

#The rule
01The front end validates to be kind to the user. The back end validates to stay alive.
02Make the safe thing the default thing. Then forgetting is not possible.
03A boundary earns its keep the day the thing behind it is replaced.
04Store the pointer, not the copy. Then filter by the pointer, every query.
05Store the recipe next to the shreds, so you can turn the dial up later.
06Hand out a ticket, keep the facts. Then logging someone out is one DELETE.
07Roles are data. Permissions are code. Deny by default.
08Routes ask for a job, never for a badge.
09Count the nouns in the rule you want. Then count the parameters you have.
10A permission needs a scope, so the scope goes in the URL.
11Rate-limit the thing the attacker has only ONE of.
12Reject a library when its defaults are wrong. Take it when no decisions are left.
13CORS is advice to a browser. It stops nobody with curl.
14The best answer to "which cross-origin setting?" is to stop being cross-origin.
15A library can be right about the facts and wrong about your situation.
16Reading is CORS, writing is CSRF. Never the same defence.
17Strip is safe. Reject is safe and honest.
18Hide it, or charge for it. Those are the only two moves against an oracle.
19An audit row that vanishes with the person it accuses is not evidence.
20A value can travel beside the query. An identifier has to be part of it.
21A 4xx is the caller's fault, so name the field. A 5xx is yours, so tell the log.
22"Logged in" is not a fact the page holds. It is a question the page asks.
23Hiding a button is a hint. The server is the gate. Ship both, trust one.
24403 is about you and runs first. 404 is about the row and is deliberately vague.
25Send the value you want, never the verb. Then a retry and a double-click are the same event.
26A create is not idempotent. When you cannot make it safe to repeat, make it hard to repeat.
27A default is where a typo hides. The four variables that decide safety get none.
28A 204 carries no body, so the id you filter by is the id you sent.
29One fact, one reader. A snapshot and a live read can disagree, and dead code has no failing state.
30A list with no limit lets the caller pick your memory. Count to a place, or look one up.
31Paging changes the shape of the cache, and a declared type is believed rather than checked.
32Testability is a property of the import graph, not of the function. And the cache keeps what did not change.
33The list is a question, so the filter belongs in the key. And a write that changes membership can no longer be patched in by hand.
34The log is a second wire out of the app and nothing guards it. Log the fields you chose, never a whole object; redaction is the net under that rule, not the rule.
35The shell expands the glob before the runner sees it, so a correct test file never ran and the suite stayed green. A pass reports only on the files the runner was handed.

Traps that bit you personally

  • node:test runs test files in parallel processes. Two files keying fixtures on Date.now() delete each other's rows. (L10)
  • @fastify/rate-limit's global: true attaches after a route's own hooks, so a blocked request still pays for requireAuth. (L12)
  • origin: true plus credentials: true reflects any origin and leaks logged-in data. (L13)
  • HSTS from localhost pins your own browser for a year. Manual fix, per browser. (L15)
  • setQueryData<Task[]> on a paged cache compiles clean and throws — tasks?.map is not a function. The component's errors were caught, the three cache writes were not. (L31)
  • Mutating data.pages[0].items updates the cache and re-renders nothing. React compares references. (L31)
  • zod chains run left to right: z.email().trim() validates the untrimmed string. (L18)
  • Half a normalisation is worse than none — a lower-cased throttle key with a case-sensitive lookup. (L18)
  • request.params holds raw strings until zod coerces them — so a 401 audit row records "249", not 249. (L19)
  • Every model cascades from User except AuditLog, on purpose. A cascade there deletes the evidence. (L19)
  • A cross-origin fetch sends no cookie without credentials: "include". Same URL, same tab: 401 vs 200. (L22)
  • document.cookie is "" while signed in — HttpOnly, by your own choice in L6. There is no client-side answer. (L22)
  • A React Query staleTime on the session query is how long a destroyed session still looks signed in. Auth needs staleTime: 0. (L22)
  • A test cannot import tasks.ts: ERR_MODULE_NOT_FOUND: Cannot find package '@/lib'. The @/ alias is a Vite rule, copied into tsconfig, and Node reads neither. (L32)
  • setQueryData after an edit that changes nothing gives back the same object. Assert on contents, not identity, or your first test fails against correct code. (L32)
  • A filter left out of the query key means 0 requests when the user changes it. No error, no wrong data — the screen just does not react. (L33)
  • A cursor from one filter, sent with another, is not an error: measured 1 row where 4 belong. A cursor is a bookmark in one list. (L33)
  • z.coerce.boolean().parse("false") is true. It is Boolean(), and a conversion that can never fail is not a check. Use z.stringbool(). (L33)
  • Prisma contains is case sensitive — 2 of 4 real matches. mode: "insensitive". (L33)
  • ...(done && { done }) silently drops done: false. Test === undefined. (L33)
  • request.log.error({ err }) prints every property the error carries — measured, a passwordHash and a full SQL string next to the stack you wanted. (L34)
  • A pino redact wildcard is one level: *.passwordHash misses err.user.passwordHash. (L34)
  • "**.passwordHash" is not pino syntax. It does not throw, does not warn, matches nothing, and the value prints in full. (L34)
  • A log test under LOG_LEVEL=silent reads an empty stream and passes forever. Assert the log is not empty first. (L34)
  • stream: undefined does not compile under exactOptionalPropertyTypes — TS2769. Same flag, same spread, one lesson after L33. (L34)
  • An unquoted src/**/*.test.ts in package.json: 22 files on disk, 21 run. npm run uses sh, where ** is one level. Quote the pattern. (L35)
  • The same command gave 154 through npm test and 155 pasted into zsh. Only the shell differed. (L35)
  • A pattern that matches nothing is passed through untouched — which is the only reason web escaped the same bug. That is luck, not a design. (L35)
  • A missing test file is not a failure and not a skip. It has no row. The expected count is the only thing that catches it. (L35)
