Password hashing

Quick-reference sheet. Print it. Numbers come from OWASP Password Storage, checked 2026-09-01.

The one rule

You never need the password back. Store a slow, salted hash. Compare in constant time. Never log it, never email it, never put it in a reply.

Algorithms, in OWASP order

#AlgorithmMinimum settingsUse when
1argon2id19 MiB memory, 2 iterations, parallelism 1Default for anything real. Needs a package.
2scryptN=2^17 (~128 MiB), r=8, p=1argon2id not available. Built into Node. Our choice for now.
3bcryptwork factor ≥ 10, cap input at 72 bytesLegacy systems only. Not for new code.
4PBKDF2SHA-256: 600,000 iters · SHA-512: 220,000 itersOnly when FIPS-140 compliance forces it.

Never use md5, sha1, sha256, or sha512 alone. They are built to be fast, and fast is the vulnerability.

Vocabulary

WordWhat it isSecret?
HashOne-way shredding. No key, no undo.Stored openly
SaltRandom bytes, unique per user, mixed in before hashing. Kills shared hashes and lookup tables.No. Stored next to the hash.
PepperOne extra secret, shared by all rows, kept outside the database (env var / KMS).Yes. Optional extra layer.
Work factorThe slowness dial (N for scrypt, memory+iterations for argon2).Stored openly, inside the hash string
Timing attackLearning a secret from how long an answer took.Fixed by timingSafeEqual

Stored format

scrypt$131072$8$1$<salt-base64>$<hash-base64>
  |       |    | |      |             |
  scheme  N    r p      salt          the shreds

Why the settings live in the string: you can raise the work factor next year and old rows still verify, because each row says how it was made. Re-hash on next successful login to upgrade quietly.

Node snippets (no dependencies)

import { randomBytes, scrypt, timingSafeEqual } from "node:crypto";
import { promisify } from "node:util";
const scryptAsync = promisify(scrypt);

const N = 2 ** 17, r = 8, p = 1, KEY_LEN = 64;
const MAX_MEM = 256 * 1024 * 1024;   // Node refuses this N without it

// hash
const salt = randomBytes(16);
const key = await scryptAsync(plain, salt, KEY_LEN, { N, r, p, maxmem: MAX_MEM });
const stored = `scrypt$${N}$${r}$${p}$${salt.toString("base64")}$${key.toString("base64")}`;

// verify  (same salt, same settings, read from the row)
timingSafeEqual(actual, expected);   // never ===

Input rules

RuleValueWhy
Minimum length8 charactersOWASP / Copenhagen Book floor
Maximum length64–256 charactersLong enough for passphrases; caps hashing cost as a denial-of-service guard
Allowed charactersAll Unicode, spaces includedBlocking characters only weakens passwords
Silent trimmingNeverChanging input means the user cannot log in with what they typed
Composition rulesSkip them“One capital, one symbol” pushes people to Password1!
